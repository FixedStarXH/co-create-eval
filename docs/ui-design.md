# 前端页面设计

项目：人机协同创造力评测系统  
版本：V1.1（2026-11-02）  
设计状态：页面结构与低保真线框已完成；P04 已选定方案 2 并制作可交互的前端原型，尚未开展用户试测。  
对应当前需求：[需求规格](requirements.md)、[项目结构](architecture.md)、[API 规则](api.md)；任务内容见 [任务与评分量规](tasks-and-rubric.md)。

P04 视觉参考：[方案 2 桌面截图](../前端原型-方案2/qa-desktop.png)；[原型说明](../前端原型-方案2/README.md)。原型用于界面与交互核对，不是可采集研究数据的正式系统。

## 1. 设计目标

让参与者始终知道“当前做什么、还剩多少时间、内容是否已保存”；让教师在不知道创作条件的情况下独立评分；让管理员迅速发现缺失数据。页面中清楚区分 AI 辅助评价和教师评价。

本版以桌面浏览器完成正式任务为基线，推荐设计宽度为 1366—1440 像素。研究收集时尽量使用相近的屏幕和浏览器环境。手机可阅读任务与报告，但正式创作页提示使用电脑。

## 2. 视觉与交互原则

| 项目 | 设计规则 |
| --- | --- |
| 风格 | 安静、清晰的教育研究工具；避免装饰性 AI 光效 |
| 主色 | 蓝色 #2563EB，用于主要按钮、当前章节、关键链接 |
| 背景 | 浅灰蓝 #F8FAFC；编辑面板白色 #FFFFFF |
| 正文 | 深灰蓝 #172033；次级文字 #657188 |
| 状态色 | 成功 #257A56、提醒 #A86113、错误 #B42318 |
| 字体 | 系统中文无衬线字体；正文 15—16 像素，标题 20—28 像素 |
| 间距 | 8 像素基础网格；卡片内边距 20—24 像素 |
| 操作 | 每页只有一个最突出的主操作；危险或不可逆操作需确认 |
| 可访问性 | 输入框有明确标签，键盘可操作，状态不只靠颜色表达 |

按钮文案应描述动作，例如“保存初始想法”“提交最终方案”，避免只写“确定”。计时与自动保存状态在编辑页持续可见。任务的 AI 条件和独立条件采用同一编辑器结构，以减少界面差异对实验的干扰。

## 3. 页面地图

    参与者：P01 研究说明 → P02 任务说明 → P03 初始构思
                                      ↓
             P06 个人报告 ← P05 提交与问卷 ← P04 创作工作台

    评分教师：P07 待评列表 → 匿名作品评分 → 提交锁定

    研究管理员：P08 任务与进度 → 缺失检查 / 数据导出

参与者页面顶部始终显示五步进度：“说明、任务、构思、完善、报告”。问卷放在提交之后、报告之前。教师和管理员有独立导航，不进入参与者创作流程。

## 4. 参与者页面

### P01 研究说明与进入

**目标：**让参与者理解数据用途，再进入任务。

**版式：**居中单列卡片，最大宽度约 720 像素。依次显示研究简介、任务时长、会保存的数据、退出方式、参与者编号输入框、同意选项和“开始”按钮。研究说明可展开查看全文；同意框不能预勾选。

**状态：**编号无效时在输入框下方说明原因；未同意时禁用开始；重复编号登录时恢复其已开始的会话，不新建重复任务。

### P02 任务说明

**目标：**参与者在开始计时前读懂情境、提交格式和阶段安排。

**版式：**左侧任务情境与约束，右侧“你需要提交什么”和“5 分钟构思 + 20 分钟完善”的时间卡。底部主按钮为“我已理解，开始构思”。

**内容：**任务名称、目标学生、课堂时长、五项作品字段、可用资源及提醒。此页不展示评分教师、实验序列或其他参与者结果。

### P03 初始构思

**目标：**在 AI 功能关闭时留下用户自己的核心想法。

**版式：**顶部为阶段名称、倒计时和保存状态；中间为三个简短输入区：

1. 我想解决的关键问题是什么？
2. 我准备让学生做什么？
3. 这个活动可能怎样判断学习效果？

底部固定“保存初始想法并继续”按钮。输入区允许简短条目，不显示终稿 500—800 字提示。时间到时先尝试保存，再按统一规则进入下一阶段；保存失败必须提示并保留本地文本。

### P04 创作工作台

**目标：**把任务要求、作品编辑和 AI 建议放在同一视野，减少反复跳页。方案 2 采用“上方章节导航 + 宽幅编辑器 + 底部建议栏”。

| 区域 | 内容 | 关键交互 |
| --- | --- | --- |
| 顶部状态栏 | 任务名、当前阶段、剩余时间、保存状态、作品预览 | 保存状态说明最近保存时间与失败状态；正式系统还需退出入口 |
| 章节导航 | 目标、学生任务、活动流程、资源、评价方式 | 点击切换对应作品字段 |
| 任务摘要 | 情境与关键约束 | 可展开完整要求，创作时始终可查 |
| 中央编辑区 | 五段式作品编辑器的当前章节 | 自动保存、手动保存、查看版本、提交前预览 |
| 底部建议区 | AI 建议卡片、改写后采纳、忽略 | 建议不可自动进入作品；正式系统增加提问、回复与来源记录 |

协同条件显示底部 AI 建议区；独立条件应保持编辑区和主要按钮的位置一致，底部预留相同尺寸的非交互占位区。此处理仍需在研究试测中检查界面差异是否影响创作行为。默认焦点落在作品编辑区。聊天消息不自动写进作品，用户必须主动选择。

“插入到作品”先让用户选择目标字段；“修改后插入”打开可编辑的小窗口，保存用户修改后的内容与来源消息编号；“忽略”记录动作。原型当前仅实现对当前章节的“改写后采纳”和“暂不采纳”；正式系统须补齐目标字段选择、消息编号与过程日志。手动复制或改写可能无法准确归因，报告只展示确实记录到的行为。

**必须设计的状态：**AI 正在回复、AI 超时、保存中、保存失败、版本冲突、剩余时间不足、阶段结束。AI 失败时编辑器仍可继续使用；提交前展示五项字段和未保存提醒。

当前原型仅提供计时、演示保存状态、章节编辑与预览、预置 AI 建议的主动采纳。刷新后内容重置；不可用其采集正式研究数据。

### P05 最终提交与体验问卷

**目标：**让参与者检查作品并完成任务后反馈。

先展示只读终稿预览和“返回修改 / 确认提交”。点击确认后由服务端锁定终稿，并跳到问卷。问卷逐题展示 1—5 分选项；AI 专属题只在协同条件出现。页面说明“提交后作品不能自行修改”。重复点击提交不应产生第二份终稿。

### P06 个人测评报告

**目标：**解释本次作品得到什么评价，评价依据是什么。

报告顶部显示任务名称、报告状态和时间。教师未完成评分时，显示“AI 辅助评价已生成，教师评价待完成”；教师完成后将两种评价分区展示。三维结果使用并列横向分数条，不用一个不明来源的总分。下方依次是教师评语、AI 辅助意见、初始想法与终稿对照、协作过程时间线。布局见 [测评报告线框图](assets/测评报告线框图.svg)，图中的分数仅为占位示例。

每条过程结论应能展开查看原始版本或消息。独立条件的报告显示作品修订时间线，不出现空的 AI 对话模块。报告用说明文字提示：结果仅代表本次任务表现。

## 5. 评分教师页面 P07

**待评列表：**显示随机作品编号、任务题目、是否已评；不显示参与者姓名、创作条件、AI 评分、初稿/终稿标签或其他教师评分。正式评分对象仅为终稿。

**评分详情：**左侧只读作品，右侧固定评分表。三个维度各有 1—5 分按钮，点击维度名称可打开完整量规。填写具体评语后才能提交，建议各写一项优点与改进点。提交前有确认框，提交后锁定原始评分。布局见 [教师评分线框图](assets/教师评分线框图.svg)。

**异常：**作品缺失或不符合教学活动方案时可标记“待复核”，并填写原因；系统不以 0 分代替无效作品。教师评分中途离开可保存草稿，但草稿不进入正式报告。

## 6. 研究管理员页面 P08

管理员首页只显示研究运行状态：参与人数、已完成场次、待评分作品、数据缺失和 AI 调用失败。下方提供任务配置、四序列分配、量规版本、匿名数据导出入口。进度表的每场状态应能展开到“初稿、终稿、问卷、AI 调用、教师甲、教师乙”，便于发现具体缺项。

任务或量规一旦用于正式场次，应复制为新版本再修改。导出前给出字段和匿名化预览，避免误将身份对应表混入研究数据。

## 7. 页面组件清单

- StudyHeader：标题、进度、计时和保存状态。
- TaskBrief：情境、约束与提交清单。
- IdeaForm：初始构思三个输入区。
- ArtifactEditor：终稿五段式编辑器。
- VersionDrawer：关键版本与时间线。
- ChatPanel：AI 消息、提问框、建议操作。
- SuggestionInsertDialog：选择字段和修改后插入。
- RubricScore：1—5 分按钮与锚点说明。
- ResultBar：单维分数条，显示评价来源。
- MissingDataBadge：明确标注“待生成、待评分、调用失败、无效”。

## 8. 前端交付与验收

开发顺序建议：P01—P04 的无 AI 流程 → 保存与恢复 → AI 底部建议区及对话 → 提交问卷 → 教师评分 → 报告 → 管理台。P04 方案 2 的可交互原型已制作；下一步应让 2—3 名同学仅凭页面文字走一遍任务，记录误解的按钮和信息。该检查用于修改界面文案，不替代 W7 的完整系统试测。

最低验收：参与者能看见当前阶段和保存状态；任务要求在创作时可见；AI 建议不会自动覆盖作品；教师在评分前看不到创作条件；报告区分辅助评价与教师评价；管理台能明确标出缺失数据。
