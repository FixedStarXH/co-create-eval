# 人机协同创造力评测系统：完整项目需求基线

版本：V2.0 草案（2026-11-02）  
阶段：需求设计，尚未据此完成前后端系统  
配套任务与评分量规：[tasks-and-rubric.md](tasks-and-rubric.md)  
视觉模板：用户选定的“图片 2”；现有 [P04 前端原型](../前端原型-方案2/README.md) 用来验证视觉方向，不代表系统已实现。

> **一句话定义：**参与者在同一系统完成两场教育创意任务；系统记录独立构思、作品修订与 AI 协作过程；AI 在提交后生成辅助评价，两名教师对匿名终稿独立评分；系统向参与者展示有来源的报告，并向研究管理员导出可复核的匿名数据。

## 1. 项目边界与交付标准

### 1.1 项目的三个交付成果

1. **可运行的软件：**浏览器前端、API 后端、持久化数据库、可配置的真实文本模型接口、安装运行说明及自动化测试。
2. **可研究的数据链：**任务与条件分配、知情同意、初稿、终稿、过程版本、AI 对话和建议处理、问卷、AI 辅助评价、教师原始评分及审计事件可关联和导出。
3. **可复核的评测记录：**功能测试、试测记录、匿名原始数据和可重算的统计结果。示例数据与真实采集数据须明确区分。

### 1.2 测评对象

本系统评价**特定教育创意任务中作品的新颖性、教育适切性和可实施性**，并呈现协作过程。它不诊断个人稳定创造力，不自动判定“人贡献百分比”，不把 AI 分数与教师分数混成一个总分。教师对匿名终稿的评分是主要评价来源；AI 评分是辅助结果。

### 1.3 必做范围与延期范围

| 等级 | 范围 | 交付判定 |
| --- | --- | --- |
| P0：端到端必做 | 三角色权限、两任务四序列、知情同意、两阶段创作、保存恢复、真实 AI 对话、建议处理、终稿锁定、AI 辅助评价、双教师盲评、个人报告、管理员进度与匿名导出 | 任一试测会话可从进入系统走到报告和导出；原始数据可复核 |
| P1：正式研究前完善 | 体验问卷、异常恢复、版本冲突、评分分歧提示、打印报告、配置冻结、数据质量校验 | 正式收集时可发现并解释缺失和失败 |
| P2：延期 | 多模态作品、多模型比较、公众注册、自动贡献比例、跨领域常模、社交功能 | 不进入首个可运行版本的完成标准 |

**完整项目不等于单张页面。**当前图片 2 只规定参与者创作工作台的风格，其他页面须使用同一设计语言，但各自完成真实业务操作。

## 2. 用户、权限与数据可见性

| 角色 | 登录方式 | 可以做 | 不可以看 |
| --- | --- | --- | --- |
| 参与者 | 管理员发放的研究编号与一次性或可重设访问凭证 | 同意、完成分配给自己的两场任务、查看本人报告 | 他人的作品、条件、评分和后台配置 |
| 评分教师 | 独立账号及密码 | 查看分配给自己的匿名终稿和量规、提交或暂存本人评分 | 参与者身份与条件、AI 评分、其他教师评分、初始构思、研究导出 |
| 研究管理员 | 独立账号及密码 | 配置版本、发放编号、监控缺失、处理异常、导出匿名数据 | 不应直接修改已提交的原始作品和教师原始评分；特殊更正须留下审计记录 |

权限由**后端逐接口验证**，前端隐藏按钮不能代替授权。教师与参与者不能使用同一个账号对同一作品操作。研究编号与真实姓名的对应关系如有需要，应在系统外或单独受保护的数据表中保存，不进入默认研究导出。

## 3. 研究流程与业务状态

### 3.1 每位参与者的两场任务

两道任务 A、B 见 [任务与评分量规](tasks-and-rubric.md)。每场均为 **5 分钟独立构思 + 20 分钟完善作品**。四种序列由管理员在活动开始前轮流或按预生成名单分配：

| 序列 | 第一场 | 第二场 |
| --- | --- | --- |
| S1 | A + AI | B + 独立 |
| S2 | A + 独立 | B + AI |
| S3 | B + AI | A + 独立 |
| S4 | B + 独立 | A + AI |

分配后保存序列号、场次、任务版本、条件和分配规则版本，不因参与者表现改变。两场之间显示休息与第二场入口；不能跳过第一场直接进入第二场。

### 3.2 单场状态机

`待开始 → 独立构思 → 完善作品 → 已提交/待问卷 → 待教师评分 → 评分完成`；没有有效终稿而超时则进入“已过期/缺稿”，退出研究则进入“已退出”。

- 独立构思期间，无论条件如何都不提供 AI。阶段结束保存不可覆盖的初始想法快照。
- 完善阶段，两种条件使用相同任务、编辑字段、计时和保存机制；AI 条件开放模型对话，独立条件不开通 AI 接口。
- 服务端记录阶段开始与截止时间；浏览器倒计时只显示服务端剩余时间。初始构思可提前提交并等待 5 分钟截止，完善作品可提前提交；20 分钟到时先按统一的短时收尾窗口尝试保存，再锁定终稿或标记缺稿。细则见 [API 与状态规则](api.md)。
- 提交终稿是幂等操作；重复点击返回同一终稿，不产生新版本。提交后参与者不能再改写。
- 问卷和 AI 辅助评价是独立完成标志，失败不能抹掉终稿。教师评分完成前报告可以显示“待评分”，不得显示虚构分数。
- 中途退出后，凭证有效时恢复本人最近一次成功保存的草稿及正确阶段；失败状态有明确提示和重试入口。

### 3.3 设计模式与研究模式

开发或演示可使用清晰标记的测试编号和模拟模型响应，以便离线演示。**研究模式**必须接入真实模型，固定任务、量规、提示词和模型配置；若 AI 不可用，管理员应看到阻断提示，不能把模拟响应混入正式数据。两种模式的数据物理隔离或以不可混淆的环境标识区分，导出默认只选研究模式。

| F-02 | P0 | 自动分配两场任务 | 四序列分配可查；同一参与者恰有 A、B 各一场和 AI、独立各一场 |

| F-06 | P0 | 自动与手动保存 | 停止输入约 5 秒保存，阶段切换和提交前强制保存；成功、进行中、失败状态可见；刷新恢复成功稿 |

| F-09 | P0 | 建议处理 | 可“采纳”“修改后采纳”“暂不采纳”；记录来源消息、目标章节、最终插入文本和时间；AI 文字从不自动写进作品 |
| F-10 | P0 | 终稿提交 | 预览五字段与未保存提醒；确认后锁定；重复提交幂等；保存最终快照 |

| F-13 | P1 | 第二场引导 | 第一场结束后显示休息提示和第二场入口；最终展示两场完成状态 |

### 4.2 AI 服务

| ID | 优先级 | 需求 | 验收条件 |
| --- | --- | --- | --- |
| A-01 | P0 | 可配置真实文本模型 | 后端从环境配置读取提供方地址、密钥、模型标识、超时和参数；浏览器响应及导出不包含密钥 |
| A-02 | P0 | 服务端提示词 | 创作提示词包含任务约束和“提供建议，不替用户决定”；提示词有版本号；正式研究期间不静默更新 |
| A-03 | P0 | 对话请求 | 每次请求有唯一请求号；记录用户提问、回复、时间、模型、提示词版本、状态和错误类型；同一请求号重试不重复记消息 |
| A-04 | P0 | 调用边界 | 非 AI 条件、独立构思期、已提交会话均由后端拒绝调用；前端隐藏入口仅辅助体验 |
| A-05 | P0 | 提交后辅助评价 | 只读取锁定终稿和同一量规；返回新颖性、教育适切性、可实施性三维各 1—5 分、引用的作品证据、理由和一条改进建议 |
| A-06 | P0 | 结果校验与失败 | 校验结构、分数范围、证据字段及作品归属；失败保存原始回复和错误状态；报告显示“辅助评价暂不可用” |
| A-07 | P1 | 研究配置冻结 | 模型、参数、提示词、量规和任务版本可在研究批次中追溯；更改须新建版本并记录时间 |
| A-08 | P1 | 费用与频率约束 | 管理员配置每场最大轮次、单次超时和重试次数；用户看到等待与超时信息；超限不删草稿 |

**接入策略：**第一版只接一种文本模型，后端以独立适配层对接可配置的模型 API。供应商由可用账户、稳定性和学校要求决定；前端不直接调用模型。模型输出被当作不可信外部数据，后端先校验再入库或展示，作品展示时转义危险内容。

## 5. 页面需求与图片 2 的视觉模板

### 5.1 全站设计语言

| 设计元素 | 统一规则 |
| --- | --- |
| 风格 | 专业文档工作台：克制、清晰、信息优先；不使用光效、AI 科幻背景或大面积装饰图 |
| 主色 | 蓝色 `#2563EB`；深色标题 `#172033`；次级文字约 `#657188`；页面背景 `#F8FAFC`；内容面板白色 |
| 结构 | 白色顶栏、浅灰页面、细边框、小圆角；主操作使用蓝色按钮，次级操作为白底描边或文字按钮 |
| 文字 | 中文无衬线，正文约 15—16 px；页面主标题约 20—24 px；说明与状态可小一档但保持可读 |
| 反馈 | 保存、计时、加载、失败均同时用文字表达，不只靠颜色；焦点清晰可见 |
| 设备 | 正式创作以 1366—1440 px 桌面为基线；平板可阅读和操作；手机至少能查看任务和报告，并提示桌面创作 |

图片 2 的结构只作为 P04 的**视觉与版式模板**：顶部状态栏、横向五章节导航、任务摘要、宽幅编辑画布、底部 AI 建议区。其他页面沿用配色、字体、边框、按钮和信息密度，不强行复制编辑器结构。

| P02 任务说明 | 参与者；任务情境、五字段、5+20 分钟、当前场次 | 开始独立构思 | 第一/第二场、任务版本、尚未计时 |

| P08 研究管理 | 管理员；配置、分组、进度、缺失、导出 | 发布配置 / 导出 | 未冻结、已冻结、数据缺失、导出预览与审计 |

### 5.3 P04 交互详规

1. **顶部：**系统名、任务与阶段、服务端剩余时间、最后保存状态、作品预览入口。正式系统应显示明确的“返回/退出并保存”。
2. **导航：**“目标 / 学生任务 / 活动流程 / 资源 / 评价”五标签与作品五字段一一对应；切换前先保存当前字段的本地状态，后台保存失败不清空输入。
3. **任务摘要：**默认显示一句任务要求，展开可看完整情境、约束和提交清单；不随编辑器滚动消失。
4. **编辑区：**当前字段标题、写作提示、基础格式工具、正文、字数、修订状态；编辑器内部可滚动；切换字段和刷新后恢复最后一次成功保存内容。
5. **底部协作区：**AI 条件可提问、查看回复、切换历史消息并处理选中建议；区内有明确的“改写后采纳”“直接采纳”“暂不采纳”。直接采纳也须先选目标章节并确认。独立条件保留相同高度的中性任务信息区，以减少页面尺寸差异；不得提供任何模型调用。
6. **版本入口：**可查看初始想法、关键过程版本和当前稿，显示时间与来源。初稿和终稿只读。
7. **预览与提交：**预览列出全部五字段及未填写提示；提交时强制保存，保存成功且用户确认后才锁定。

### 5.4 可访问与易用性要求

表单必须有可见标签和错误位置；键盘可完成主流程；弹窗打开后焦点进入弹窗、关闭后返回触发按钮；颜色对比、缩放和窄屏不造成内容丢失；计时临近结束有文字提醒但不遮挡编辑。试测时安排 3—5 人在无口头指导条件下完成流程，记录误解、漏点和完成时间。

## 6. 数据需求与关系

### 6.1 最小数据表

| `draft` | 会话、五字段内容、修订号、最后保存时间 | 可更新；旧修订号不能覆盖新稿 |
| `artifact_version` | 会话、阶段、内容、修订号、时间、关键节点标记 | 初始/关键/终稿快照不可修改 |
| `chat_request` / `chat_message` | 会话、请求号、用户输入、模型回复、模型/提示词版本、状态、耗时、错误 | AI 失败也保留请求记录；独立条件无消息 |
| `suggestion_action` | 来源消息、动作、目标字段、插入前后文本、时间 | 每次显式操作可追溯；不推断未记录采纳 |
| `ai_assessment` | 终稿版本、量规/模型/提示词版本、原始回复、校验结果、状态 | 与教师评分隔离；失败不填 0 |
| `teacher_rating` | 匿名作品、教师、三维原始分、评语、状态、提交时间 | 一教师对一作品至多一份正式评分；草稿与正式评分区分 |
| `survey_answer` | 会话、问卷版本、题目编号、原始 1—5 值、时间 | 不只存均值 |
| `audit_event` | 操作者、会话、事件类型、时间、必要的变更摘要 | 阶段、异常、更正与导出可追踪 |
| `study_batch` | 批次、模式、任务/量规/模型/提示词版本、冻结时间 | 正式研究的数据配置可复现 |

### 6.2 完整性与隐私规则

- 使用服务端时间并统一存储时区；呈现时再转换为本地时间。每条作品、消息、评分都能追到会话和配置版本。
- 正式研究数据的身份对应信息与研究数据分开。默认导出使用研究编号，不含姓名、电话、明文凭证、模型密钥和内部管理备注。
- 原始评分、消息、问卷、版本和错误状态均保留；报告中的均分、轮次等是可重算的派生值。
- 数据缺失以 `pending / failed / invalid / excluded` 等状态表达，不使用 0 分代替。
- 数据备份、访问权限、保留期限和退出研究后的删除或排除流程，在正式研究前按学校要求写入研究说明并配置。

## 7. 后端接口边界

接口以 `/api` 开头，采用 JSON；下载导出文件的接口除外。每个请求由后端鉴权、校验会话归属和状态；错误返回稳定错误码、可读信息及请求号。

| 领域 | 预期接口能力 |
| --- | --- |
| 身份 | 参与者凭证进入/恢复、教师与管理员登录/退出、当前用户信息 |
| 配置 | 获取本人当前任务；管理员创建、预览、发布和冻结任务/批次/量规 |
| 会话 | 开始场次、读取当前状态与服务端剩余时间、进入下一阶段、恢复草稿 |
| 作品 | 以修订号保存草稿、读取版本、提交初始快照、预览与幂等提交终稿 |
| AI | 发送对话请求、查询请求状态与消息、处理建议、提交后触发/查询辅助评价 |
| 问卷 | 读取题项、保存逐题回答、提交问卷 |
| 教师 | 获取匿名队列、读取匿名终稿和量规、暂存/提交评分、标记待复核 |
| 报告 | 读取本人两场报告、查看证据与版本、打印视图 |
| 管理 | 进度与缺失、异常审计、匿名导出及导出预览 |

对写操作使用明确的请求号或幂等键：AI 对话、阶段切换、最终提交、教师正式评分均应避免网络重试产生重复记录。密码只保存安全摘要，模型密钥只读取服务器环境变量；外部模型调用集中在一个后端服务模块。

## 10. 验收场景：项目做到什么程度才算“完整”

1. 管理员建立研究批次并配置 A/B 任务、四序列、量规与模型参数；发布后旧版本保持可追溯。
2. 用两名测试参与者分别进入 S1、S2；未同意者无法开始，正常参与者可完成第一场、休息、第二场。
3. AI 场和独立场均先完成无 AI 的初始构思；独立场后续始终不能从接口调用 AI。
4. AI 场真实调用模型得到建议；用户修改后主动采纳一条、拒绝一条；后台可查到请求、回复、动作和目标章节。
5. 创作时刷新页面可恢复最后成功稿；保存冲突和 AI 超时均不丢当前编辑内容。
6. 终稿提交后内容锁定，重复请求只得到同一终稿；问卷逐题保留。
7. AI 辅助评价在提交后产生三维结构化结果；模拟不完整回复时，报告显示失败状态且保留原始错误。
8. 两名教师分别打开匿名终稿并评分；各自提交前无法看到对方及 AI 分数；两份原始评分均保留。
9. 参与者报告正确区分 AI 与教师来源，并能追溯到作品片段和过程事件；教师未评分时显示待完成。
10. 管理员导出匿名数据，从导出文件可重建上述场次与报告数值；缺失和异常有状态与原因。

以上场景是首个完整版本的最小验收条件。正式评测还需试测、任务与量规审定、配置冻结以及真实参与者和评分教师的数据；功能实现本身不等于评测结论成立。

## 11. 实施顺序与待确认事项

建议按四个可运行增量开发：

1. **无 AI 的完整链路：**身份、同意、任务/序列、初始构思、编辑保存、终稿、教师评分和报告。
2. **真实 AI 接入：**对话、请求日志、建议动作、提交后辅助评价及失败状态。
3. **研究管理：**问卷、版本冻结、进度、缺失检查、匿名导出和审计。
4. **试测与评测证据：**自动化测试、3—5 人试测、修订冻结、正式采集与分析。

正式研究前必须由实际条件确定：可用的模型服务及预算、学校知情同意与数据保存要求、两名评分教师、研究样本与截止日期。上述因素影响配置与研究实施，但不改变本需求中的核心数据链和三角色系统边界。
