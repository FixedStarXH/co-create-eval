# 测试、部署与开发里程碑

版本：V1.0（2026-11-02）  
状态：开发执行与验收计划；尚无正式系统测试结果  
需求基线：[requirements.md](requirements.md)

## 1. 交付定义

项目只有同时满足以下四项，才能称为“完整的前后端系统”：

1. 前端 P01—P08 与后端 API、数据库真实联通；刷新、重登后能够读取之前成功保存的数据。
2. AI 条件通过后端接入真实文本模型，保留对话和评分原始记录；未配置或失败时明确提示，不以预置文案冒充真实结果。
3. 两名教师对匿名终稿独立评分，管理员可导出匿名原始数据，报告能由原始数据重算。
4. 提供依赖锁定、环境变量模板、数据库迁移、演示数据、安装说明和关键流程自动化测试。

当前已完成的是**设计文档和 P04 视觉原型**；本文件列出后续工程验收，不把计划写成已通过的测试。

## 4. 手工端到端验收脚本

1. 管理员创建 DEMO 批次，发布 A/B 题、量规、问卷、提示词和模型配置；创建两位教师与四名参与者，覆盖 S1—S4。
2. 参与者 1 输入编号但拒绝同意，确认不能开始；之后同意，检查记录版本与时间。
3. 完成 5 分钟独立构思，早交时停在等待状态；到期进入 20 分钟完善。AI 场进行至少两轮真实提问，一条改写后采纳，一条忽略。
4. 断开网络编辑一段文字，看到保存失败和本地缓冲；恢复后保存，刷新检查最后成功稿。用两个标签页制造修订冲突，确认不会静默覆盖。
5. 提交并重复点击，检查只有一份 FINAL。填写问卷；模型辅助评分成功后查看来源和证据。再用故障适配器测失败显示。
6. 两名教师分别登录同一匿名作品，核对页面不含研究编号、条件、AI 分数和对方评分；各自给分并提交。尝试重改，确认锁定。
7. 管理员检查进度与缺失，导出 DEMO 批次；用校验脚本重算报告均分与记录数。正式研究开始前重复此脚本，但使用真实冻结配置和不含演示数据的独立数据库。

每一步保存日期、操作者、系统版本、截图或测试日志、实际结果和失败单号；不在文档中预填“通过”。

## 5. 本地开发与部署说明应包含的内容

正式项目 `README.md` 应给出可复制的步骤：

1. 安装受支持的 Python 与 Node.js 版本；根据锁文件安装前后端依赖。
2. 复制 `.env.example` 为本地配置，填写数据库地址、Cookie 密钥、AI 提供方地址/模型/密钥；说明 DEMO 与 RESEARCH 的差别。
3. 运行数据库迁移；只在 DEMO 模式初始化演示账号与假数据。
4. 启动 FastAPI 和 Vite；检查 `/api/v1/health`、前端首页以及 OpenAPI 文档。
5. 运行后端测试、前端类型检查/构建、关键交互测试。
6. 正式部署时使用同源入口提供前端和 API，配置访问控制、备份目录与日志目录；记录运行版本和批次配置。

研究模式启动前的检查：数据库可写且已备份；AI 密钥与模型真实可用；A/B 任务、量规、问卷和提示词已冻结；两名教师账户可登录；演示账号不可访问研究批次；网络与浏览器环境已在现场测过。缺任一关键项，管理员页面给出阻断状态，不允许标记“正式开始”。

## 6. 备份、恢复与异常处理

- 每场试测前备份数据库；正式收集日开始前和结束后各做一致性备份。备份文件与原库分开保存并限制访问。
- 恢复演练至少一次：从备份在另一目录恢复，核对参与人数、初稿/终稿数、聊天数、教师评分数和导出摘要。
- 模型故障时，当前作品与计时按统一规则继续；记录故障起止、影响场次及研究排除/保留决定，不为失败场次补造 AI 对话。
- 数据库写失败时，不显示“已保存”；前端保留用户当前文本、提示重试并停止不可逆提交。管理员看到故障场次列表。
- 教师不能评分的作品标为待复核；不得用 0 分填补。所有人工更正需保留原始记录与理由。
- 数据库迁移先在演示库验证；正式库迁移前备份，记录迁移编号和回退办法。已采集样本的任务、量规、模型配置保持版本可追溯。

## 7. 交付证据与数据质量门槛

| 交付环节 | 需要提供的证据 |
| --- | --- |
| 需求与设计 | 需求、角色、用例、验收标准、架构和数据模型 |
| 系统实现 | 可运行代码、真实运行截图、环境配置说明和接口文档 |
| 系统测试 | 自动化测试结果、真实模型连通测试、试测问题及修复记录 |
| 实际评测 | 匿名原始数据、教师原始评分、导出校验和可复核的分析结果 |

正式数据分析前必须检查：每位参与者是否有互补两场、初稿和终稿是否存在、独立场有无 AI 调用、两教师评分是否齐全、问卷缺失、AI 失败与版本混用。缺失保留为缺失；先按预先确定的排除规则生成样本清单，再计算统计结果。产品能力与样本数据结论分别报告。

## 8. 工作量控制

优先完成能采集可信数据的闭环：身份/分组 → 两阶段作品 → 保存/终稿 → AI 对话与评分 → 双教师评分 → 报告/导出。图表、打印样式和管理统计以清晰、可复核为准，不为装饰牺牲主流程。图片 2 的视觉迁移应在 I0 完成设计 token 和 P04 组件，但不得延迟服务端保存和权限等 P0 功能。
